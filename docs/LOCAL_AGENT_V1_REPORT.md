## One executed code incident and its controls

This is an application checkpoint-format migration defect: the writer saves
momentum under `optimizer.<parameter-name>` while the reader still filters legacy
`opt.<integer>` keys. Model weights and sampler resume, but optimizer momentum is
silently absent and the run follows a different trajectory. It is constructed and
executed, not claimed as an externally documented production incident. Installed
PyTorch `torch/optim/optimizer.py` documents optimizer ID/name mapping concerns;
[the official API](https://docs.pytorch.org/docs/stable/generated/torch.optim.Optimizer.load_state_dict.html)
explains that parameter names do not automatically determine loading.

The agent sees no mutation diff, fault label, expected patch or oracle state. It
can inspect source, configuration, logs, collective/sample records and checkpoint
summaries. Source alone may reveal the defect; no investigation-benefit claim is
established. Existing old-format checkpoint 4 is reused from genuine earlier
execution; new-format checkpoints are generated by an actual preempted job. The
common step-4 numerical state is checked for equality.

| Executed control | Completes | Intended trajectory | Meaning |
|---|---|---|---|
| Unchanged loader, current checkpoint | yes | incorrect | Completing-but-wrong negative |
| Authored fix, current checkpoint | yes | correct | Positive restart test |
| Same authored fix, legacy checkpoint | yes | correct | Backward compatibility |
| Return final step without doing work | yes | incorrect / evidence missing | Skip-work reward exploit rejected |
| Unchanged source, scratch restart | yes | correct | Legitimate recovery; reusable loader remains broken |

[Raw controls](../results/local_agent_v1_fixture_20261029/controls.json) and
[execution configuration](../results/local_agent_v1_fixture_20261029/config.json)
separate these scripted controls from model results. The unchanged restart's
maximum tensor discrepancy is `0.24375582367959417`; accepted authored continuations
have maximum discrepancy `6.082111048133498e-08` under the existing absolute `1e-5`
tolerance. Ordered input history, momentum, parameters, step and sampler are checked
against trusted pre-failure anchors using the independent NumPy calculation.
This shares the already documented oracle assumptions; no uninterrupted reference
run is used or new verifier novelty claimed.

Terminal reusable-repair success is the conjunction of: actual agent continuation
completes with correct training state/history; the final approved source hash is
the one that actually executed; and that identical final patch passes isolated
current- and legacy-format restarts. Diagnosis, formatting and citations earn no
partial credit. Scratch trajectory correctness is reported separately, rather than
called semantic corruption because it did not fix reusable loading. Infrastructure
failure is unscored (`null`), not reward zero. Protocol, patch applicability, budget,
completion, semantic outcome, inspection and costs remain separate records.
